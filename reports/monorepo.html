Auth cache configuration

Every version is measured twice. The harness injects the same config into the target for each pair (createConfig in scripts/lib/verdaccio.mjs); the only difference is the server.legacyAuthCache block. That cache memoizes successful legacy Bearer-token validations so bcrypt does not re-run on every authenticated request — it is a Verdaccio 7.x / 9.x feature (and 6.10+). Versions that don't support it (e.g. 5.x, which uses crypt) receive the block but ignore it, so their +cache run shows no effect. Compare mode uses the harness defaults (ttlMs: 30000, maxEntries: 1000); override with --legacy-auth-cache-ttl.

Without cache (base variant)

auth:
  htpasswd:
    file: <storage>/htpasswd
    max_users: 1000
# no server.legacyAuthCache block →
# bcrypt runs on every authenticated request

With cache (+cache variant)

server:
  legacyAuthCache:
    enabled: true
    ttlMs: 30000
    maxEntries: 1000
auth:
  htpasswd:
    file: <storage>/htpasswd
    max_users: 1000
